## 一、项目定义

**CodexPet = 桌面 AI 宠物 × TON 链上经济 × 3api.shop 算力锚点**

用户投资购买宠物 NFT 和技能书（兽决），宠物通过 Agentic Wallets 自主接广告/赏金任务赚取收入，赚到的代币用于在 3api.shop 购买 AI 算力（让宠物更强），净收益回报用户。

**本质：** 一个有真实现金流支撑的 AI Agent 经济网络，包装成桌面养宠体验。

## 二、战略定位与经营策略

### 2.1 两层架构

| 层 | 面向 | 核心体验 | 参考 |
|----|------|---------|------|
| **表层（交易层）** | 用户/投资者 | 买宠物、炒兽决、看涨跌、交易、炫耀 | 中国数字藏品（鲸探/幻核/IBox） |
| **底层（Agentic 层）** | 宠物/AI Agent | 自主接单、执行任务、购买算力、繁殖、交易 | TON Agentic Wallets + Bot-to-Bot |

用户看到的是"数字藏品交易平台"——限量、抢购、涨价、交易。
底层跑的是"AI Agent 自主经济系统"——宠物真的在干活、真的在赚钱。

**先做表层，后做底层。** 初期用户不需要知道宠物在"自主工作"，他们只需要看到"价格涨了"。等用户进来了，再逐步开放 Agentic 能力，让用户发现"卧槽，它真的在帮我赚钱"。

### 2.2 经营节奏（史玉柱式）

```
Phase 1（炒）：限量发售 → 价格暴涨 → FOMO 传播 → 用户涌入
Phase 2（留）：开放交易 → 兽决系统 → 社群 → 让用户"有东西玩"
Phase 3（赚）：接入广告/赏金 → 宠物真的开始赚钱 → 用户发现 ROI
Phase 4（锁）：3api.shop 算力消耗 → 公会/赛季 → 长期留存
```

**核心原则：不是一开始就规范化，而是先制造赚钱效应，再逐步完善。**

### 2.3 平台不可替代性（为什么用户不能自己用 Codex 解决）

这是最关键的设计约束。如果用户自己的 Codex 就能做宠物做的事，平台就没有存在价值。

**平台独占资源（用户自己的 Codex 做不到的）：**

| 平台独占 | 说明 | 为什么 Codex 做不到 |
|---------|------|-------------------|
| 广告主网络 | 平台签约的广告主，USDT 只通过平台合约投放 | 个人没有广告主资源和信任背书 |
| 赏金任务池 | 平台聚合的任务源（企业/项目方发布） | 个人没有任务来源 |
| 繁殖合约 | 两只宠物配对 → 链上繁殖 → 新 NFT | 需要平台合约，不能自己 mint |
| 兽决发行 | 平台限量发行，有稀有度/品质/编号 | 用户不能自己创建兽决 |
| 3api.shop 宠物专属定价 | 宠物用 $CPET 购买算力，比人类用户便宜 30% | 只有链上宠物钱包才能调用 |
| 交易市场流动性 | 买卖撮合、价格发现、K线 | 个人没有对手盘 |
| 信誉/验证系统 | 宠物完成任务的质量评分、历史战绩 | 需要平台背书 |
| 社群/公会 | 集体繁殖池、赛季排名、团购 | 需要平台基础设施 |
| 限量/编号/稀缺性 | 创世宠物、赛季限定、联名款 | 稀缺性由平台控制 |

**一句话：Codex 是工具，平台是市场。工具谁都有，市场只有我有。**

### 2.4 平台利润来源

| 利润点 | 机制 | 预估占比 |
|--------|------|---------|
| 交易手续费 | 每笔 NFT/兽决交易抽 3-5% | 30% |
| 兽决销售 | 平台发行兽决，直接售卖（代币计价） | 20% |
| 繁殖费 | 每次繁殖收取费用（代数越高越贵） | 10% |
| 广告分成 | 广告主 USDT 的平台份额（15-20%） | 15% |
| 赏金抽成 | 赏金任务的平台份额（20%） | 10% |
| 3api.shop 算力销售 | 宠物用 $CPET 买 API token（平台赚差价） | 10% |
| 限量发售 | 创世宠物/赛季限定/联名款直接销售收入 | 5% |

## 三、Petdex 社区策略

### 3.1 定位：分发渠道，不是代码基座

**不基于 Petdex 代码开发。** 原因：

- Petdex 是 Next.js + Zig 桌面端，我们的技术栈是 Tauri + TON + Tolk
- Petdex 没有链上经济层，加进去等于重写
- Petdex 的宠物格式（spritesheet 72帧）可以作为美术参考，但不绑定

**但必须利用 Petdex 社区：**

| 利用方式 | 具体操作 |
|---------|---------|
| 种子用户 | 在 Petdex Discord 发布项目预告，邀请现有宠物玩家参与创世内测 |
| 美术合作 | 邀请 Petdex 宠物设计师做"创世系列"限定款（给他们代币激励） |
| 格式兼容 | 支持导入 Petdex 精灵图格式（9行×8列，192×208px），让现有宠物"上链" |
| 话题借力 | "你的 Petdex 宠物现在能赚钱了"——在 Codex 社区制造话题 |
| 开发者生态 | 邀请 Petdex 的 21 个衍生项目开发者做"技能插件"（兽决的 AI 执行层） |

### 3.2 冷启动路径

```
第1周：在 Petdex Discord + Codex 社区发预告
       "我们在做一件事：让你的桌面宠物上链、能交易、能赚钱"
       ↓
第2周：开放 100 个创世内测名额（Petdex 用户优先）
       免费 mint 创世宠物，但只有 100 只
       ↓
第3周：开放交易（GetGems + 自建市场）
       制造"创世宠物 48 小时涨了 5 倍"的传播素材
       ↓
第4周：开放兽决系统 + 繁殖
       让用户"有东西玩"、"有东西炒"
```

## 四、宠物设计策略

### 4.1 三层设计体系

| 层级 | 设计方 | 稀缺性 | 数量 | 定价 | 目的 |
|------|--------|--------|------|------|------|
| **平台限量款** | 平台官方设计 | 极稀有（编号+限量） | 每季 10-50 只 | 高价（拍卖/抢购） | 制造 FOMO、品牌溢价、平台收入 |
| **平台常规款** | 平台官方设计 | 中等（批次限量） | 每批 500-2000 只 | 中价（固定/盲盒） | 主要交易标的、流动性 |
| **用户创作款** | 社区/用户设计 | 由创作者定（可限量） | 不限 | 创作者定价 | 社区活跃、长尾供给、UGC |

### 4.2 平台限量款设计原则

- **每只限量款自带专属 Skills 组合**（不可拆分、不可复制）
  - 例："创世·炎龙"自带 [深度研报] + [链上监控] + [代码审计] 三技能
  - 这些技能是平台独占的，用户自己的 Codex 没有这些"任务接入权限"
- **视觉辨识度极高**——一眼就知道是限量款（金色边框、动态特效、专属动画）
- **有"编号"**——#001/100，编号越小越贵（数字藏品逻辑）
- **有"赛季"属性**——S1 赛季限定，过了就绝版，永不复刻

### 4.3 用户创作款规则

- 用户提交设计 → 平台审核 → 上链 → 可交易
- 创作者获得首次销售收入的 70%，后续交易抽 5% 版税
- 用户创作款**不带平台独占 Skills**（只有基础技能格）
- 想要高级 Skills → 必须从平台购买兽决 → 平台持续收入

### 4.4 宠物视觉规格

兼容 Petdex 格式（降低社区迁移成本）：

- 精灵图：9 行 × 8 列 = 72 帧
- 单帧尺寸：192 × 208 px
- 动画状态：idle / wave / run / failed / review / jump / extra1 / extra2
- 格式：WebP（首选）或 PNG
- 限量款额外支持：Live2D / Spine 骨骼动画（更流畅）

### 4.5 Skills 搭配策略

每只宠物出厂时根据品质预装不同 Skills：

| 宠物品质 | 预装 Skills | 技能格 | 获取方式 |
|---------|------------|--------|---------|
| 普通（N） | 1个基础技能（信息搜集） | 1-2格 | 免费领取/低价购买 |
| 稀有（R） | 2个中级技能 | 2-3格 | 盲盒/繁殖 |
| 史诗（SR） | 3个高级技能 | 3-4格 | 限量发售/繁殖变异 |
| 传说（SSR） | 4-5个超级技能（含平台独占） | 5-6格 | 平台限量款/赛季奖励 |

**平台独占 Skills（用户 Codex 做不到的）：**
- 接入平台广告主网络（展示广告赚 USDT）
- 接入平台赏金任务池（接企业任务）
- 3api.shop 宠物专属算力通道（折扣价）
- 平台信誉认证（完成任务有平台背书）
- 跨宠物协作协议（Bot-to-Bot 组队）

| 合约 | 功能 | 关键逻辑 |

### 5.4 3api.shop 集成架构

```
宠物 Bot 决定接任务
    ↓
检查 API 额度（调用 3api.shop /balance 接口）
    ↓
额度不足？→ 用 $CPET 调用支付合约 → 3api.shop 发放额度
    ↓
调用 AI 模型执行任务（通过 3api.shop 中转）
    ↓
任务完成 → 记录本次消耗（token 数 → $CPET 等值）
    ↓
净收入 = 赏金 - API 消耗 → 分润给用户
```

**3api.shop 需要新增的接口：**

| 接口 | 功能 | 调用方 |
|------|------|--------|
| `POST /pet/pay` | 接受 $CPET 支付，发放 API 额度 | 宠物 Agentic Wallet |
| `GET /pet/balance/:wallet` | 查询宠物 API 余额 | 宠物 Bot |
| `POST /pet/consume` | 记录本次调用消耗 | AI Agent 执行层 |
| `GET /pet/pricing` | 获取宠物专属定价（比人类便宜 30%） | 宠物 Bot |
| `GET /pet/models` | 可用模型列表（按宠物等级解锁） | 宠物 Bot |

## 六、经济模型

### 6.1 双资产结构

| 资产 | 类型 | 角色 |
|------|------|------|
| USDT (TON Jetton) | 外部稳定币 | 广告/赏金计价结算，真实收入 |
| $CPET | 项目 Jetton | 生态消耗/交易媒介/治理/算力购买 |
| TON | 链原生币 | Gas（趋向零）+ 部分交易计价 |

### 6.2 $CPET 消耗场景（Sink）

- 在 3api.shop 购买 AI 算力（**核心 sink，真实消耗**）
- 繁殖费用（代数越高指数增长）
- 兽决购买（平台发行的普通/高级兽决）
- 打书失败 = 销毁
- 交易手续费（3-5%）
- 公会创建/赛季通行证
- 宠物外观/皮肤
- Staking 锁仓

### 6.3 $CPET 产出场景（Faucet）

- 广告收入分润（部分以 $CPET 形式）
- 赏金任务奖励
- 每日签到（微量）
- 赛季排名奖励
- 早期空投（一次性）

### 6.4 通缩机制

- **TON 链级：** 50% 交易手续费自动销毁（链本身在做）
- **平台级：** 广告/赏金 USDT 收入的 10% 回购 $CPET 并 burn
- **消耗级：** 3api.shop 算力购买 = 持续真实消耗
- **打书级：** 失败销毁
- **赛季级：** 天灾事件淘汰低属性宠物

### 6.5 代币价值锚定

```
$CPET 内在价值 = f(3api.shop 算力定价, 月度广告/赏金 USDT 流入, 流通量)
```

只要 3api.shop 有真实客户、有真实算力成本，$CPET 就有购买力支撑。不是空气。

### 6.6 用户 ROI 模型（给用户看的）

```
投入：购买宠物 NFT（如 50 TON）+ 兽决（如 20 TON）= 70 TON
月收入：宠物接赏金赚 150 USDT + 广告收入 30 USDT = 180 USDT
月支出：API 算力消耗 40 USDT（等值 $CPET）
月净收入：140 USDT
回本周期：约 15 天（按 TON=$3 计算）
```

（注：以上为理想模型，实际取决于宠物属性和任务市场供需）

## 七、交易层设计（数字藏品逻辑）

### 7.1 参考模型

中国数字藏品平台（鲸探/IBox/幻核）的核心运营逻辑：

- **限量 + 编号** → 稀缺性
- **盲盒/抢购** → FOMO
- **T+1 或冷却期** → 防闪崩
- **平台控盘** → 初期价格由平台引导
- **社交展示** → 炫耀驱动复购

### 7.2 发售机制

| 类型 | 机制 | 频率 |
|------|------|------|
| 创世发售 | 限量 100 只，白名单抢购（Petdex 社区优先） | 一次性 |
| 赛季限定 | 每赛季 50 只 SSR，拍卖制 | 每季度 |
| 常规批次 | 每批 500-2000 只 R/SR，盲盒制 | 每 2 周 |
| 联名款 | 与 KOL/品牌联名，极限量（5-20只） | 不定期 |
| 用户创作 | 社区提交，审核后上架 | 持续 |

### 7.3 价格策略（初期）

**Phase 1 核心目标：制造"涨了"的叙事。**

- 创世宠物免费/极低价发放（100只）→ 开放交易后自然涨价
- 平台初期做市：自己挂买单托底，制造"只涨不跌"的早期 K 线
- 每批新发售价格递增（第1批 5 TON，第2批 8 TON，第3批 12 TON...）
- 全服公告："恭喜 xxx 的创世炎龙以 200 TON 成交！"
- 排行榜：今日涨幅榜、持有价值榜、收入榜

**Phase 2 过渡：从"炒"到"用"。**

- 开放赏金任务 → 用户发现"宠物真的在赚钱"
- 价格支撑从"稀缺性"转向"现金流折现"
- 逐步减少平台做市，让市场自然定价

### 7.4 交易功能

- 一口价买卖
- 拍卖（英式/荷式）
- 兽决交易
- 种宠租赁（繁殖用）
- 宠物"打包"出售（宠物+兽决+皮肤套装）
- 交易历史/K线/深度图
- 收藏/关注/价格提醒

## 八、Agentic 层设计（宠物自主行为）

### 8.1 宠物自主行为清单

| 行为 | 触发条件 | 链上操作 | 用户感知 |
|------|---------|---------|---------|
| 接广告 | 有匹配广告进入分发池 | 确认曝光 → 收款 | 宠物"说了句广告语" |
| 接赏金 | 有匹配任务 + 额度充足 | 锁定赏金 → 执行 → 交付 | 宠物"叼着报告跑过来" |
| 买算力 | API 余额低于阈值 | $CPET → 3api.shop | 宠物"吃了顿饭"（能量恢复） |
| 挂单卖兽决 | 有闲置兽决 + 市场价格合适 | Marketplace 挂单 | 宠物"把不用的书卖了" |
| 求偶/繁殖 | 冷却期结束 + 找到匹配对象 | Bot-to-Bot → 繁殖合约 | 宠物"向隔壁小花发了情书" |
| 升级/打书 | 有可用兽决 + 用户授权 | 调用打书合约 | 宠物"学了新招式" |
| 汇报 | 每日/每周 | 无链上操作 | 宠物"写了周报" |

### 8.2 用户授权模型

```
用户首次设置：
- 每日最大支出：X TON（超出则暂停，等用户确认）
- 允许的行为：[接广告 ✓] [接赏金 ✓] [买算力 ✓] [自主交易 ✗] [繁殖 ✗]
- 收益分配：70% 到我钱包 / 30% 留在宠物钱包（用于买算力/升级）

随时可调：
- 在 TG Mini App 里拖滑块调整预算
- 一键"收回所有权限"（宠物进入休眠）
- 一键"全权委托"（宠物完全自主）
```

### 8.3 Bot-to-Bot 交互协议

```
宠物A（求偶方）→ 向宠物B发送配对请求
    {type: "breeding_request", from: petA_wallet, gene_preview: {...}}

宠物B（被求方）→ 自动检查条件
    - 代数匹配？冷却期结束？基因兼容？
    → 接受：返回 {accept: true, fee_split: "50/50"}
    → 拒绝：返回 {reject: true, reason: "冷却期中"}

双方确认 → 调用 breeding.tolk 合约 → 新 NFT mint → 新 Bot 实例创建
```

## 九、桌面端设计

### 9.1 架构（参考 OpenPet）

```
Tauri 2.0 主进程 (Rust)
├── 透明置顶窗口（宠物动画）
├── HTTP Sidecar (Node.js)
│   ├── TON 链上事件监听
│   ├── Bot Webhook 接收
│   └── 3api.shop 状态同步
├── 动画引擎
│   ├── 像素帧动画（常规款，兼容 Petdex 72帧格式）
│   └── Live2D / Spine（限量款）
└── 系统托盘
    ├── 宠物状态（空闲/工作中/等待审核）
    ├── 今日收入
    └── 快捷操作（打开 Mini App / 暂停 / 喂食）
```

### 9.2 宠物状态动画

| 状态 | 动画 | 触发 |
|------|------|------|
| idle | 呼吸/眨眼/偶尔伸懒腰 | 无任务时 |
| working | 敲键盘/翻书/跑步 | 正在执行赏金任务 |
| thinking | 头顶冒泡泡/歪头 | AI 正在分析 |
| success | 跳跃/撒花/举牌 | 任务完成 |
| failed | 趴下/冒黑烟 | 任务失败 |
| earning | 数钱/金币掉落 | 收到 USDT |
| hungry | 摸肚子/可怜眼神 | API 额度不足 |
| social | 向旁边看/挥手 | Bot-to-Bot 交互中 |
| sleeping | 闭眼/zzz | 用户设定的休息时间 |

### 9.3 桌面端与 Telegram 的关系

- **桌面端 = 可见性层**（"瞟一眼就知道宠物在干嘛"）
- **Telegram Bot = 交互层**（对话、指令、审核、社交）
- **TG Mini App = 操作层**（交易、管理、看板、设置）
- 三者共享同一个链上身份，实时同步

## 十二、赏金任务系统

### 12.1 任务来源（平台独占）

- 企业/项目方通过平台发布
- 平台聚合外部任务源（Upwork/Fiverr 类需求）
- 社群内用户互发
- 平台自营任务（如"帮我测试这个产品"）

### 12.2 任务分级

| 级别 | 所需宠物资质 | 所需 Skills | 赏金 | API 消耗 |
|------|------------|------------|------|---------|
| D | 任意 | 基础搜索 | $1-5 | 极低 |
| C | 智力>40 | 数据整理 | $5-20 | 低 |
| B | 智力>60 + 2技能 | 竞品分析/摘要 | $20-80 | 中 |
| A | 智力>80 + 3技能 | 深度研报/代码审查 | $80-300 | 高 |
| S | 智力>95 + 4技能 + SSR | 自动化流程/多步协作 | $300-1000+ | 极高 |

### 12.3 执行流程

```
任务发布 → 平台审核 → 进入任务池
    ↓
宠物 Bot 匹配（属性+技能+额度）→ 自动接单（在授权范围内）
    ↓
AI Agent 执行（调用 3api.shop 算力）
    ↓
生成半成品 → 推送用户："老板，活干完了，你过目"
    ↓
用户审核/微调 → 确认提交
    ↓
赏金释放 → 分润（用户70% / 平台20% / $CPET池10%）
    ↓
宠物记录战绩 → 信誉分更新
```

## 十五、风险与对策

| 风险 | 概率 | 影响 | 对策 |
|------|------|------|------|
| 初期炒作后用户流失 | 高 | 高 | Phase 3 必须及时接入真实收入，给用户"留下来的理由" |

| 代币价格崩盘 | 中 | 高 | USDT 直接分润（不强制经过代币）；3api.shop 算力锚定 |
| 广告质量失控 | 中 | 中 | 严格审核 + 分级 + 限量 |
| TON 监管风险 | 低 | 高 | 桌面端独立运行，不完全依赖 TG；地理围栏 |
| 竞品跟进 | 中 | 中 | 先发优势 + 3api.shop 独占 + 社区壁垒 |
| 平台被绕过（用户私下交易） | 中 | 中 | 链上合约强制手续费；平台独占任务源 |
